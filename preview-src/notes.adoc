[#new.release-notes-filter]
== New features and functionality
The latest release of ThoughtSpot Cloud contains several new and enhanced features.

The features described in these release notes may have one of the following statuses.

[.borderless,width=88%]
|===
|Feature statuses

|[.badge.badge-beta-relnotes]#Beta#

Beta features are incomplete and may change before GA. They are enabled for select customers to collect feedback and have limited documentation. Beta features are disabled by default. Your administrator must contact {support-url} to enable them.

|[.badge.badge-early-access-relnotes]#Early Access#

Early Access features are complete and supported, but not yet enabled by default. You can try them before GA, with full documentation available. Early Access features are disabled by default. Refer to the feature documentation for how to enable them.

|[.badge.badge-ga-relnotes]#GA#

General Availability (GA) features are usually enabled by default for all customers. They are fully supported. If the GA feature is not enabled by default, the process for enabling it is noted in the documentation.
|===

=== For the Business User

[#spreadsheet]
Spreadsheets [.badge.badge-ga-relnotes]#GA#::
// Naomi. jira: SCAL-324098. docs jira: SCAL-324099
// PM: Peeyush.
The spreadsheet interface puts a familiar, editable grid directly on your live data. Save your work as an Answer that stays searchable, shareable, and governed like anything else in ThoughtSpot.

* *Columns and formulas on live data*: Build new metrics with 70+ built-in functions. Every formula runs as a live query and persists as governed logic your team can reuse.
* *Shape your view instantly*: Sort, filter, conditional formatting, and text and number formatting help you focus on what matters, applied live on the data.
* *Save as a governed Answer*: Your spreadsheet becomes a searchable, shareable object with security and lineage intact, never a disconnected export.
* *Built for real datasets*: Scroll seamlessly through large result sets and switch to full-screen mode for focused analysis.
+
For more information, see
xref:spreadsheet.adoc[Spreadsheet].

[#spotter-connector-marketplace]
Spotter connector marketplace [.badge.badge-ga-relnotes]#GA#::
// Mark. jira: SCAL-330286. docs jira: SCAL-330287
// PM: Shannon
Spotter now features a browsable catalog with more than 100 third-party connectors, making it easier than ever to discover and add third-party data integrations. Every user can browse, search, and explore available connectors, including one-click options like Slack and Web Search, plus connectors for services like Microsoft Teams that guide you through setup. Your administrator or users with the `CanManageSpotter` privilege can add and configure connectors for your organization. If you don't see a specific MCP server in the catalog, any MCP-compliant server can still be added manually. The Spotter marketplace connectors are available to all users in Spotter by selecting *Settings > Connectors*. This feature will be rolled out in the first weekly patch after the 26.10.0.cl release. For more information, see xref:spotter-connector-marketplace.adoc[].

[#charts-added]
Charts added to the new charts library [.badge.badge-ga-relnotes]#GA#::
// Mark. jira: SCAL-299459, SCAL-299450, SCAL-299440. docs jira: SCAL-299460, SCAL-299451, SCAL-299441
// PM: Anshul.
The new charts library expands to add waterfall, pareto, candlestick, funnel, and heatmap charts, bringing enhanced analytical flexibility and modernized styling across search, Spotter, and Liveboards. This release introduces support for multi-panel trellis and faceting modes, new multivariate axis configuration logic, and expanded customization options — including independent color controls for increment and decrement bars on Waterfall charts, refined gradient and label positioning on Heatmaps, and enhanced axis formatting on pareto charts. For more information, see xref:charts-library-new.adoc#new-chart-types[New chart types].

[#liveboard-depedency]
Liveboard dependency management [.badge.badge-ga-relnotes]#GA#::
// Mary. jira: SCAL-323877. docs jira: SCAL-323878
// PM: Siddhant.
Liveboard dependency management is now generally available (GA). Admin users can now delete data model columns even if they're in use on Liveboards. When a data model column that a Liveboard depends on is deleted, ThoughtSpot now detects the impact and shows you exactly what's broken instead of displaying a generic error or silently failing.

[#command-palette]
Command palette redesign::
// Mark. jira: SCAL-323049. docs jira: SCAL-335174
// PM: Arpit. add screenshot. add to release notes.
The command palette has a new, polished look and feel that introduces full support for light and dark modes, smooth open and close animations, and a cleaner layout with updated icons and filter chips. Search results now highlight matching terms for faster scanning, and improved loading and visuals make it easier to understand what's happening as you search — all while keeping the same keyboard shortcuts and commands you already know.

[#faster-chart]
Faster chart rendering for charts in Spotter answers [.badge.badge-beta-whats-new]#Beta#::
// Mark. jira: SCAL-330485. docs jira: SCAL-330486
// PM: Anshul.
Spotter now uses progressive rendering to display charts instantly as soon as your query returns results, rather than waiting for the chart generation to complete. An initial chart appears immediately, then automatically updates in the background with refined styling and data-aware formatting — with a subtle indicator letting you know the enhancement is in progress. Any manual adjustments you make always take priority. The result is a noticeably faster and smoother experience when exploring data with Spotter. To enable this feature, contact {support-url}. For more information, see xref:charts-agentic-progressive-rendering.adoc[].

=== For the Analyst

[#liveboard-contextual]
Liveboard contextual filtering [.badge.badge-early-access-relnotes]#Early Access#::
// Mary. jira: SCAL-298005. docs jira: SCAL-298006
// PM: Dilip.
Liveboard creators can now scope filters and parameters to a specific tab or group, instead of applying them globally across the entire Liveboard. This makes it easier to build focused, information-dense Liveboards where consumers can analyze a specific area without inadvertently affecting unrelated visualizations. To enable this feature, contact your administrator.
+
When a Liveboard with tab or group filters is imported into a cluster where this feature is disabled, the scoped filters are removed on import.
+
For more information, see
xref:liveboard-filters.adoc[Liveboard filters].

[#liveboards-with]
Liveboards with column-security rules [.badge.badge-ga-relnotes]#GA#::
// Mary. jira: SCAL-284082. docs jira: SCAL-284083
// PM: Siddhant.
The enhanced behavior of Liveboards built with column security rules is now generally available (GA). If users restricted by column security access the Liveboard, they can see and interact with the Liveboard filters and visualizations, but cannot edit the Liveboard as a whole. If such inaccessible columns are used as filters in the Liveboard, the Liveboard will no longer be blocked. Schedules now honor column security rules, and each recipient receives their own report based on their column security rule assignments.
+
For more information, see
xref:security-data-object.adoc#csr-liveboard[Column security rules on Liveboards].

Muze Studio now includes an AI chat assistant that lets you build and refine custom charts using natural language. Publishing from object lists [.badge.badge-ga-relnotes]#GA#::
// Mary. jira: SCAL-321926. docs jira: SCAL-333386
// PM: Sejal
Publishing, and publishing from object lists are now generally available (GA). You can now publish, unpublish, and manage the publishing state of Answers, Liveboards, and Models directly from the list page view without having to open each object individually.
+
The *Publish*, *Unpublish*, and *Manage publishing* options are available in the row-level action menu on the Answers, Liveboards, and Data Workspace list pages. The publish and unpublish options allow you to select target Orgs, handle dependents, and confirm the action.
+
Publishing is a multi-Org feature. These actions are only visible in multi-Org environments where object publishing is enabled. You must be in the primary Org and be a cluster administrator to see the publish and unpublish actions.
+
For Models specifically, the publish action is not available for objects authored by a superuser or system user.
+

[#user-impersonation]
Act as (User impersonation) [.badge.badge-early-access-relnotes]#Early Access#::
// Rani. jira: SCAL-325381, SCAL-325379. docs jira: SCAL-325382, SCAL-325380
// PM: Swarnima. request image.
ThoughtSpot administrators can now impersonate a specific user to troubleshoot issues directly, without requiring screen shares or shadow accounts. To initiate a session, the administrator first requests the user to configure their *Act as user* preferences on their profile page, where the user sets the permitted time window for impersonation. Sessions expire automatically at 60 minutes, and the administrator can end the session at any time using the *Exit session* button. The user receives email notifications when a session starts and ends. All actions taken during the session are captured in audit logs.
+
This feature is available for ThoughtSpot Analytics customers with the xref:admin-portal-2.adoc[new Admin Portal] enabled. Administrators can enable it from *Feature Management* > *Early Access*.
+
For more information, see xref:user-impersonation.adoc[Act as (User impersonation)]

Databricks Metric Views integration [.badge.badge-early-access-relnotes]#Early Access#::

Databricks Metric Views integration is now available in ThoughtSpot. [#llm-driven]
LLM-driven semantic integrations for formula generation [.badge.badge-beta-relnotes]#Beta#::
ThoughtSpot now uses AI to translate external semantic definitions into ThoughtSpot formulas and Models during import, delivering higher accuracy than the previous rule-based translator, especially for complex SQL expressions that the deterministic parser could not handle. This feature is supported for Snowflake Semantic Views, Databricks Metric Views, and dbt MetricFlow imports.
For Databricks Metric Views, you can provide the Metric View definition either by uploading a YAML file or by connecting directly to Databricks to retrieve the definition at import time.
+
To enable this feature, contact {support-url}.

[#secure-suggestions]
Secure suggestions in saved filter values [.badge.badge-beta-relnotes]#Beta#::
// Naomi. jira: SCAL-289352. docs jira: SCAL-289353
// PM: Prayansh
ThoughtSpot now enforces row-level security (RLS) on saved filter values in Answers and Liveboards. When a filter chip displays values from a column marked as *Secure Suggestions* in the data model, ThoughtSpot checks whether the current user has RLS access to those values before displaying them.
+
When filter values are cleared due to RLS enforcement, the user still sees data, but only the rows their RLS policy permits. An empty
filter chip on a secured column does not mean *no data*; it means the saved filter values were not applicable to this user and the RLS policy
is the active constraint.
+

To enable this feature, contact {support-url}.
// For more information on secure suggestions and RLS, see xref:rls-secure-suggestions.adoc[Row-level security: secure suggestions].
