Every Spotter answer is built from four kinds of context:

- Instructions that set behavior
- Data model semantics that give the data meaning
- Memory that captures how your business answers questions
- External context that is pulled over MCP from the sources your admin has connected

The following walkthrough shows how Spotter fetches each type of context and applies it to produce the final insight.

            <div class="ph"><b>Deterministic query plan</b><span>generated by the semantic layer, not the LLM</span></div>
            <div class="pbody"><div>
<pre><span class="kw">SELECT</span> month(close_date) <span class="kw">AS</span> month,
  <span class="kw">SUM</span>(<span class="kw">CASE WHEN</span> change_type = <span class="ct">'churn'</span>
    <span class="kw">THEN</span> -arr_change <span class="kw">END</span>) <span class="kw">AS</span> churned_arr,
  <span class="kw">SUM</span>(<span class="kw">CASE WHEN</span> change_type = <span class="ct">'downgrade'</span>
    <span class="kw">THEN</span> -arr_change <span class="kw">END</span>) <span class="kw">AS</span> downgrade_arr,
  <span class="kw">COUNT</span>(<span class="kw">DISTINCT CASE WHEN</span> change_type
    = <span class="ct">'churn'</span> <span class="kw">THEN</span> account_id <span class="kw">END</span>)
    <span class="kw">AS</span> logos_lost
<span class="kw">FROM</span> arr_changes
<span class="kw">WHERE</span> region = <span class="ct">'EMEA'</span>
  <span class="kw">AND</span> fiscal_quarter = <span class="ct">'Q2 FY26'</span>
  <span class="kw">AND</span> change_type <span class="kw">IN</span> (<span class="ct">'churn'</span>,<span class="ct">'downgrade'</span>)
<span class="kw">GROUP BY</span> 1 <span class="kw">ORDER BY</span> 1;</pre>
