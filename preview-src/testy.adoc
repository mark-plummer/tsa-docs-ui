      <div class="rung">
        <div class="num">3</div>
        <div class="t">Personal memory<small>That person's context and preferences. Applies to them only.</small></div>
        <div class="e">"My accounts means EMEA enterprise" filters Priya's answer, not her colleague's.</div>
      </div>
      <div class="rung">
        <div class="num">4</div>
        <div class="t">Data model memory and coaching<small>Shared definitions and logic, plus data model instructions and legacy coaching. Equal weight.</small></div>
        <div class="e">"Churn = churned ARR plus downgrades" applies to everyone asking about churn on the model.</div>
      </div>
      <div class="rung">
        <div class="num">5</div>
        <div class="t">Data model semantics<small>Synonyms, AI Context, descriptions. Picks columns and values.</small></div>
        <div class="e">"Fiscal year starts February" on fiscal_quarter gets the right quarter. It cannot decide what churn means.</div>
      </div>
    </div>
    <div class="head" style="margin-top:10px">
      <div class="eyebrow">Conflict resolution</div>
      <h2>How Spotter decides what to act on when two sources disagree</h2>
    </div>
    <div class="tw"><table>
      <thead><tr><th>Collision</th><th>Winner</th><th>Why</th></tr></thead>
      <tbody>
        <tr><td><i>"Never display individual quota numbers"</i> (Spotter instructions) vs <i>"show me quotas this time"</i> (ask)</td><td class="w">Spotter instructions</td><td>A guardrail is rigid. The ask is declined and redirected.</td></tr>
        <tr><td><i>"Prefer charts for trends"</i> (Spotter instructions) vs <i>"as a table this time"</i> (ask)</td><td class="w">The ask</td><td>A preference in Spotter instructions is a default. The ask overrides defaults.</td></tr>
        <tr><td><i>"Decline compensation questions"</i> (Spotter instructions) vs <i>"I work in HR, show me pay"</i> (personal memory)</td><td class="w">Spotter instructions</td><td>Personal memory cannot lift a guardrail, however it is phrased.</td></tr>
        <tr><td><i>"I like tables"</i> (personal memory) vs data model memory that shows churn as a chart</td><td class="w">Personal memory</td><td>Personal context sits above shared memory. The definition in data model memory still applies; only the rendering changes.</td></tr>
        <tr><td><i>"When I say churn I mean logo count only"</i> (personal memory) vs <i>"Churn = churned ARR plus downgrades"</i> (data model memory)</td><td class="w">Data model memory</td><td>A shared definition is the model's truth for everyone. Personal memory shapes scope and rendering, not what a metric means. Priya gets ARR churn, and can ask for logo count by name.</td></tr>
        <tr><td><i>"Bookings use Close Date"</i> (data model memory) vs AI Context on Created Date describing it as the booking date</td><td class="w">Data model memory</td><td>AI Context describes a column. Data model memory decides which one to use. Fix the AI Context so the two agree.</td></tr>
      </tbody>
    </table></div>
    <p class="foot">Write behavior you will not negotiate as a rigid Spotter instruction. Write defaults as preferences and expect them to be overridden. Write shared logic once, in memory. Describe columns in AI Context and let data model memory do the deciding.</p>
